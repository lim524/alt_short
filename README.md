# Binance Alt Short Scanner

실제 Binance USDT 결제 무기한 시장을 탐색하고, Day/Swing 근거를 확인하고, 숏 모의 시나리오를 편집·보관하는 Next.js 웹 앱입니다. 한국어 UI, 데스크톱·모바일 반응형 레이아웃을 제공합니다. 자동 주문·거래 권한·토큰 언락 기능은 없습니다.

## 실행

Node.js 22 이상:

```sh
npm ci
npm run dev
```

http://localhost:3000 → **스캔 시작** → 후보 선택 → 근거·차트 확인 → 모의 가격 수정 → **시나리오 저장**. 저장 시나리오 탭에서 원본·수정 버전·후속 결과를 확인합니다. 운영 실행은 `npm run build` 후 `npm start`입니다.

Binance 핵심 기능에는 API 키가 필요 없습니다. 선택 기능은 `.env.example`을 `.env.local`로 복사하고 서버에만 설정합니다:

| 변수                     | 용도                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------- |
| `COINGECKO_DEMO_API_KEY` | 선택형 CoinGecko Demo 제공자 접근. 키가 없더라도 공개 접근을 시도하고 실패 시 미확인 표시 |
| `OPENAI_API_KEY`         | 선택형 AI. 브라우저로 전달하지 않음                                                       |
| `OPENAI_MODEL`           | 계정에서 사용 가능한 Structured Outputs 지원 모델 ID. 기본값 없음                         |
| `AI_ACCESS_TOKEN`        | 32자 이상 개인 접근 토큰. AI 패널에서 입력하며 기기에 저장하지 않음                       |

AI는 셋 중 하나라도 미설정이면 비활성화됩니다. 키·모델·접근 토큰은 채팅이나 Git에 올리지 마세요. 제공자 결제 계정의 비용 한도도 별도로 설정하세요.

## 스캐너 동작

1. 사용자 실행 시 활성 USDT 결제 무기한 시장 전체를 조회합니다.
2. 24h quote 거래대금, 상장 14일 이상, 스프레드와 시세/호가 시각을 검사합니다. 기본 BTC·ETH 제외. 50만~100만 USDT 관찰 목록은 일반 순위와 분리합니다.
3. 가벼운 필터 통과 목록을 24h 하락률순으로 줄이고 **기본 10개, 최대 20개만 상세 분석**합니다. 따라서 전체 거래소 종목을 모두 정밀 평가한 순위는 아닙니다. UI에 분석 범위를 표시합니다.
4. 후보별 5m/15m/1h/4h/1D, BTC 비교 봉, 최근 약 1h OI, 펀딩, 양쪽 호가 100개를 조회합니다. 브라우저에서 결정론적 점수를 계산합니다.
5. 기본 5분 갱신(10/15분 선택), 화면 복귀 시 재조회. 중지하면 브라우저 요청과 예약 갱신을 취소합니다. 서버가 이미 시작한 공개 조회는 제한 시간까지 정리될 수 있습니다. 사이트가 닫혀 있거나 iOS에서 정지되면 감시하지 않습니다.

점수는 **검증 전 가설이며 확률·진입 추천이 아닙니다**. 기준·가중치·후보 수·ATR 버퍼·순 R:R은 설정에서 변경합니다. Day/Swing 가중치 합계는 각각 100입니다. 전략 설정과 위험 가정, 관심 종목은 IndexedDB에 저장합니다. 시장 유동성 필터·갱신 간격은 현재 탭 메모리에 유지됩니다.

누락 지표는 unknown/0점으로 남고 자료 충분성은 확인된 요인의 가중치 합계입니다. 기본 안전 조건 미달, 오래된 봉/시세/호가, 불연속 봉, 미래 봉, BTC 급등, 큰 5m 상승, 부족한 호가, 낮은 순 R:R이면 새 트리거를 차단합니다. 가중치 0인 요인은 충분성에 영향을 주지 않습니다.

상태는 WATCH → SETUP → TRIGGERED로 기록되고 후속 관측 가격이 손절 이상이면 INVALIDATED, 유효시간이 지나면 EXPIRED로 표시됩니다. 단일 스냅샷에서 조건을 모두 만족하면 중간 단계를 같은 측정 시각으로 기록합니다. 스캔 사이의 가격 접촉은 관찰하지 못하며 실시간 체결 이력으로 취급하지 않습니다. 기록을 실제 매매 성과로 자동 변환하지 않습니다.

## 차트와 모의 계획

Lightweight Charts에 실제 완료 봉·거래량, EMA20/50, ATR14, 최근 50봉 지지·저항을 표시합니다. 지표 근거에서 관련 봉으로 이동할 수 있습니다. 기준 시각이 현재 시간봉에 없으면 인접 범위를 보여줍니다.

- 진입: 이전 설정 봉 저점에서 1 tick 아래. 손절: 최근 20봉 고가 + ATR 버퍼.
- TP: 과거 국소 저점 중 진입 아래의 가까운 두 지지. 지지가 없으면 임의 목표를 만들지 않습니다.
- 선 편집을 켜면 차트 이동·확대를 잠그고 손잡이를 드래그할 수 있습니다. 가격이 가까워도 손잡이가 겹치지 않도록 배치합니다. 숫자 입력은 항상 사용할 수 있습니다.
- 가격 수정 후 tick 단위 반올림. 기본 레버리지 2x, TP1/TP2 기본 50/50. TP2는 `100 - TP1 비율`입니다.
- 편도 수수료·슬리피지를 진입/청산 양쪽에 반영합니다. 펀딩은 사용자가 가정한 **전체 보유기간 수취율**로 양수=숏 수취, 음수=지급입니다. 실현 횟수를 자동 추정하지 않습니다.
- 계좌 위험, 증거금 수익률, 총/순 R:R을 보여줍니다. 추정 청산가는 표시하지 않습니다.

제시 가격은 조건부 모의 값입니다. 신호 생성 전 해당 가격에서 체결됐다고 가정하지 않습니다. 현재 가격과 진입선이 다를 수 있으며 매매 성과나 리플레이에는 신호 이후 실제 가능한 진입 조건이 별도로 필요합니다.

## 펀더멘털과 AI의 범위

매핑은 검토된 `BTCUSDT`, `ETHUSDT`, `SOLUSDT`, `AAVEUSDT`만 허용합니다. 지정 CoinGecko ID·공식 홈페이지 도메인, AAVE는 Ethereum 계약 주소도 검증합니다. 나머지는 **미확인**으로 생략합니다. DefiLlama·공식 거버넌스 연계는 AAVE만 제공합니다. 임의 심볼 검색으로 자산을 자동 연결하지 않습니다.

AAVE의 검토된 protocol slug로 전체 TVL와 최근 24h 수수료/수익을 조회합니다. 전체 이력 응답 대신 작은 `/tvl/aave` 응답을 사용합니다. 공식 거버넌스 게시글은 제목·URL·게시 시각만 표시하며 내용이나 사실성을 검증했다고 주장하지 않습니다. 제공자 실패/미제공은 null/자료 없음으로 표시하고 프로젝트 실패로 해석하지 않습니다.

AI는 명시적 클릭과 개인 접근 토큰이 있어야 동작합니다. 최신 서버 자료를 다시 조회하고 **기본 전략 설정**으로 기술 근거를 구성하므로 선택된 과거 원본과는 다른 시각의 분석일 수 있습니다. 입력 스냅샷·SHA256·모델·시각·출처를 별도 보관합니다. 과거 기술 점수/가격선을 수정하지 않습니다.

환각 검증 범위를 명확히 하기 위해 자유로운 숫자·가격 예측·프로젝트 사실 서술 대신 **한정된 가설/반대 가설과 실제로 충족한 근거 ID만 선택**합니다. 수치·링크는 모델 출력에서 생성하지 않고 입력의 실측값/출처를 렌더링합니다. 서술형 심층 펀더멘털 보고서와 광범위 뉴스 수집은 확장 대상입니다. 유료 모델 호출은 키가 없는 현재 환경에서 실행하지 않았습니다.

## 저장·백업

- 원본 신호: 측정 시각·완료 봉 시각·설정/코드 버전·위험 가정·요인 점수·지지/반대 근거·원본 OHLCV/OI/펀딩/호가·추천 가격.
- 수정 계획: 독립 append-only 버전. 원본 데이터를 덮어쓰지 않습니다.
- 모의 결과: 별도 후속 상태·가격·메모. 실제 주문/체결 데이터가 아닙니다.
- 자동 측정 기록은 최근 30건만 보관합니다. 보존할 계획은 시나리오 저장을 사용하세요.
- JSON은 원본·수정·결과·최근 측정·AI 기록을 포함합니다. 가져오기 최대 20MB. 동일 ID의 다른 내용, 잘못된 스키마, 원본 없는 수정/결과는 전체 취소합니다. 현재 가져오기 상한은 원본 200/수정 1000/결과 2000/AI 1000건입니다. 매우 큰 장기 기록은 백업 분할·장기 저장 설계가 추가로 필요합니다.
- 브라우저 origin+기기 전용입니다. 서버에 개인 시나리오를 공유하지 않으며 기기 간 동기화나 영구 보관을 보장하지 않습니다.

## API·운영 예산

| 경로                                         | 기능                                           |
| -------------------------------------------- | ---------------------------------------------- |
| `GET /api/market`                            | 시장 목록, 수신/만료 시각, 경고                |
| `GET /api/market?symbol=SOLUSDT&interval=1h` | 지원 계약의 완료 봉                            |
| `GET /api/analysis?symbol=AAVEUSDT`          | 후보 1개의 다중 시간봉·BTC·OI·펀딩·호가 스냅샷 |
| `GET /api/fundamentals?symbol=AAVEUSDT`      | 검토된 매핑의 현재 자료와 출처                 |
| `GET /api/ai-analysis`                       | AI 설정 여부와 이용 제한, 비밀 값 미노출       |
| `POST /api/ai-analysis`                      | `{symbol,strategy}` 및 Bearer 개인 토큰 필요   |

Binance 고정 URL `https://fapi.binance.com`만 호출합니다. 시세/호가 30초, 거래소 메타데이터 1시간, 캔들 15초, 서버 시각 1초, 상세 호가 10초, OI 30초 캐시입니다. 상세 조회는 봉 2개씩, upstream 최대 6개, 후보 1개 전체 약 45초 제한이며 일부 실패는 경고로 반환합니다. 요청별 8초, 연결/5xx 재시도 1회, 응답 최대 8MB입니다. 418/429 후 60초 cooldown을 둡니다.

추가 예산은 **인스턴스당** 상세 분석 30회/분·동시 2개, 펀더멘털 12회/분·동시 2개, AI 3회/시간·동시 1개입니다. AI 결과 10분 캐시, 출력 800토큰·재시도 없음입니다. AI 경로 최대 90초, 상세/펀더멘털 60초를 선언합니다. 분산 인스턴스에서 한도가 공유되지 않으므로 공개 배포 시 WAF/공유 limiter 및 제공자 계정 비용 한도가 필요합니다.

문서 확인 기준 Binance weight: exchangeInfo 1, 전체 24h ticker 40, 전체 bookTicker 5, limit=300 klines 2, depth=100은 5, premiumIndex 개별 1, serverTime 1, OI history는 별도 1000회/5분 제한 및 약 1개월 보유입니다. 실제 제한은 최신 제공자 정책을 우선합니다. 국가/호스팅 지역 차단은 우회하지 않고 오류를 표시합니다.

## 검증·배포

```sh
npm test
npm run typecheck
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

실제 API 스모크 검사는 별도 서버를 3002에서 실행한 뒤 `npm run verify:live`로 수행합니다. 다른 주소는 `BASE_URL`로 지정합니다. 운영 모드에 데모 데이터 전환 기능은 없으며 합성 fixture는 테스트에서만 사용합니다.

`.github/workflows/check.yml`에 외부 서비스/AI 키 없이 실행하는 CI를 추가했습니다. 대상 저장소는 [lim524/alt_short](https://github.com/lim524/alt_short)이며 원격 CI 결과는 Actions와 최종 작업 보고에서 확인합니다. `vercel.json`은 Next.js 빌드를 준비하며 자동 배포나 cron을 설정하지 않습니다. 계정에서 프로젝트를 연결하고 서버 환경 변수를 설정한 후 배포해야 합니다. 실제 배포는 Vercel 팀/인증 미연결로 진행하지 못했습니다.

검증 결과와 남은 수용 항목은 [구현 보고서](docs/IMPLEMENTATION_REPORT.md), 운영·페이퍼 검증 절차는 [운영 인수 문서](docs/OPERATIONS.md)를 확인하세요.
