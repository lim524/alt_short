# 운영·인수 절차 (Phase 7)

## 로컬 인수

1. Node.js 22+에서 `npm ci`, `npm test`, `npm run typecheck`, `npm run build`를 실행합니다.
2. `npm start` 후 사용자가 스캔을 실행합니다. 전체 시장 수·상세 분석 범위·수신 시각·경고를 확인합니다.
3. Day와 Swing을 각각 선택하고 요인별 실제 값·기간·임계값·배점·미확인을 확인합니다.
4. 후보의 5개 시간봉을 전환하고 EMA/ATR/지지·저항, 관련 봉 이동을 확인합니다.
5. 추천값이 있는 후보에서 편집 잠금을 해제하고 가격선을 이동합니다. 숫자 입력, 손절≤진입 오류, TP 배분, 레버리지·비용 변경 후 즉시 재계산을 확인합니다.
6. 저장 → 수정 버전 재열기 → 추천값 복원 → 새로고침 → 원본 근거 유지 → 후속 모의 결과 추가 → JSON 내보내기/가져오기를 확인합니다.
7. 스캔 중지 후 예정 갱신이 멈추는지 확인합니다. 스캔 활성 상태로 화면 복귀하면 새로 조회하는지 확인합니다.

실제 API 스모크 검사는 3002에서 서버를 실행하고 `npm run verify:live`를 사용합니다. 공개 데이터·거래소/제공자 정책에 따라 실패할 수 있으므로 fixture E2E와 구분합니다.

## iPhone 실물 수용 검사 (아직 미실행)

배포된 HTTPS 주소를 Safari에서 열어 위 흐름을 반복합니다. 특히 차트 전체 화면, 편집 잠금·해제, 네 선 손잡이, 숫자 키보드, 화면 회전, 앱 전환/복귀, 브라우저 재실행 후 저장소를 확인합니다. 화면 밖/종료 상태의 감시를 약속하지 않습니다. 터치 드래그가 어렵다면 숫자 입력을 사용하고 기종·iOS 버전·상황을 기록합니다.

## GitHub 및 Vercel

대상 저장소: https://github.com/lim524/alt_short

GitHub CI는 결제 키 없이 테스트·타입 검사·빌드·fixture 브라우저 테스트를 실행하도록 구성했습니다. 실제 외부 API 검사는 CI 기본 경로에서 호출하지 않습니다. 원격 CI가 성공하기 전 이를 성공했다고 표시하지 않습니다.

Vercel 연결 시 해당 저장소를 Next.js 프로젝트로 가져오고 설치/빌드는 `npm ci` / `npm run build`를 사용합니다. 서버 환경 변수는 대시보드에서 설정합니다. AI가 필요 없다면 모든 AI 변수를 비워 둡니다. 프로젝트 접근 보호를 켜고 본인만 사용하는 것이 초기 운영 범위입니다. 세부 팀/프로젝트와 계정 인증이 확인된 뒤 배포해야 합니다.

배포 후 홈 HTTP 응답, 실제 시장·5개 시간봉, 부분 오류, 기기별 저장, AI 무키 비활성화, 사용 지역의 Binance 접근 여부를 다시 검사합니다. 로컬에서 성공해도 호스팅 국가의 접근 정책에 따라 실패할 수 있습니다. 차단을 우회하거나 다른 시장 데이터로 조용히 바꾸지 않습니다.

이 프로젝트는 사용자 키나 개인 시나리오를 서버 저장소에 수집하지 않습니다. IndexedDB는 기기별이므로 로컬 저장 기록이 다른 기기로 전송되지 않습니다.

## 비용·장애 대응

- 스캔 요청은 상세 후보 수에 비례합니다. 우선 기본 10개·5분 간격을 유지하고 사용자 요청 때만 실행합니다.
- 429/418: 최소 cooldown 이후 다시 시도하고 전체 시장 스캔 반복 클릭을 피합니다. 앱은 오래된 값으로 새 트리거를 만들지 않습니다.
- 지표/OI/펀딩/호가 누락: 미확인·차단 이유를 확인합니다. 누락을 0이나 정상으로 바꾸지 않습니다.
- 외부 매핑 실패: CoinGecko 키·정책·공식 연결과 계약 주소를 확인합니다. 심볼만으로 연결을 확대하지 않습니다.
- AI: 32자 이상 접근 토큰, 제공자 키·모델 설정과 제공자 비용 상한을 확인합니다. 키를 브라우저 환경 변수에 넣지 않습니다.
- 메모리 한도는 인스턴스끼리 공유되지 않습니다. 다중 사용자 공개 전에는 공유 예산/WAF와 사용량 측정이 필요합니다.
- 저장 오류: 시크릿 모드·용량·origin을 확인하고 보관 가능한 JSON을 내보냅니다. 원본을 덮어쓰는 방식으로 복구하지 않습니다.

## 전략 검증·페이퍼 기록

현재 성과 데이터는 없습니다. 점수·기간·배점은 가설입니다. 2~4주 운영은 절차 점검 기간이며 통계적 우위의 증거가 아닙니다.

Day/Swing을 분리하고 신호 시각·가용 데이터 시각·신호 이후 가능한 진입·손절/목표·비용·시장 국면·유동성 계층·미체결을 기록합니다. 자동 수집하지 않은 구간은 공백으로 남깁니다. 모의 결과를 실제 거래 결과와 혼합하지 않습니다. 원본 관측을 미래 가격에 맞춰 수정하지 않습니다.

후속 리플레이를 구현한다면 다음 조건을 충족해야 합니다:

- 각 결정 시각에 가용했던 완료 봉만 사용하고 과거에 존재하지 않은 최신 OI/펀딩을 재사용하지 않습니다.
- 신규/폐지 종목·생존 편향과 역사 자료 제한을 명시합니다.
- 신호 시점과 체결 시점을 구분하고 수수료·슬리피지·보유기간 펀딩을 반영합니다.
- 같은 봉에 손절/목표가 모두 닿으면 손절 우선 등 보수적 규칙을 사전 고정합니다.
- 시간 순 train/validation/out-of-sample 분리를 고정하고 테스트 구간에서 파라미터를 조정하지 않습니다.
- 전략별 신호 수·미체결·승률·평균 손익·기대값·profit factor·drawdown·MAE/MFE와 국면별 표본을 보고합니다.
- 기술만 / 기술+펀더멘털 / 기술+펀더멘털+AI를 동일 표본과 규칙으로 비교합니다. 비교 전 AI 성과 개선을 주장하지 않습니다.

이 단계는 검증 절차 문서입니다. 리플레이 실행기나 검증된 전략 성과 대시보드는 구현하지 않았습니다.
